# Generated-file guard

Agents edit generated code, vendored code, and lockfiles by hand. The edit passes, then the next
`protoc`, `openapi-generator`, or `npm install` erases it. The guard tells the agent that a file is
generated, and names its source and the command that regenerates it, when the repository says so
literally. It never runs a generator and never blocks an edit.

| Where | What you get |
|-------|--------------|
| `orient` | `generatedFiles`: the files in scope that are generated, vendored, or lockfiles |
| `blast_radius` | `generated`: the same marks for the files the diff changed |
| `verify_change` | the `generated-file-edited` finding, one receipt item per file, and `findings[]` classified by `enforcement.policy` (with `gated`) |

Each mark is `{ file, rule, matched, kind, generatedFrom, regenerateWith, evidence?, configFile?, certainty }`.

## Detection: closed rules, first match wins

| Order | Rule | Matches | `certainty` |
|-------|------|---------|-------------|
| 1 | `lockfile` | a lockfile name below (decided first, so a lockfile's own banner never hides its manifest) | `declared` |
| 2 | `header-marker` | a marker below, in the file's leading comment block (blank and comment lines before the first other line, within the first 40 lines and 8 KiB) | `declared` |
| 3 | `gitattributes` | `linguist-generated` or `linguist-vendored` set for the path (read with `git check-attr`) | `declared` |
| 4 | `path-pattern` | `*.d.ts`, `*.generated.*`, `generated/`, `__generated__/`, `vendor/`, `vendored/`, `node_modules/` | `path-pattern` |

An explicit `linguist-generated=false` (or `-linguist-generated`) in `.gitattributes` opts a path out
of the `path-pattern` rule. Use it for a hand-written `.d.ts`.

### Header markers

A header that matches none of these is **not** detected.

| Id | Recognized line |
|----|-----------------|
| `go-code-generated` | exactly `^// Code generated .* DO NOT EDIT\.$` ([Go convention](https://go.dev/s/generatedcode)) |
| `at-generated` | a comment whose first token is `@generated` |
| `generated-do-not-edit` | one comment line that says `generated` (or `auto-generated`) and `DO NOT EDIT` / `DO NOT MODIFY`, any case |
| `auto-generated-banner` | a comment line with `<auto-generated>`, `AUTO-GENERATED FILE`, `This file is/was (automatically) generated`, or `auto-generated by` / `automatically generated by` |

A comment line starts with `//`, `#`, `/*`, `*`, `--`, `;`, `<!--`, or `%`; in Markdown and text
files (`.md`, `.mdx`, `.markdown`, `.rst`, `.adoc`, `.txt`) only `<!--` counts, so a `#` heading is
never a marker. Text after the code begins, such as a marker in a string literal, is not read.

Known gaps: a header that is not in the list is not detected. For example, a generator that says
`Generated by Dagger` with no "do not edit" on the same line is missed. A hand-written script whose
own comment says its *output* is generated and not to be edited is a false positive. Use
`-linguist-generated` only for path patterns; it does not override a header.

## Source and command: literal only

`generatedFrom` and `regenerateWith` are `unknown` unless one of these names them:

| Evidence | Read from |
|----------|-----------|
| Header source line | `source: order.proto` (any case, so mockgen's `Source:`), `generated from openapi.yaml`, or `@generated from file foo.proto`, in the header comment. Resolved against the file's directory, then the root; a path that does not resolve is reported as written. |
| Config entry | A `//go:generate` directive, a `package.json` script, or a `Makefile` recipe in the file's directory or any parent directory up to the analyzed root, or a `run:` step in `.github/workflows/*.yml` at the analyzed root. The entry must name an output path (`-o`, `--out`, `--output`, `--output-dir`, `--out-dir`, `--outdir`, `--outDir`, `--output-path`, Go-style `-out`, `-output`, `-destination`, protoc `--*_out=`, or `>`) that is the file or a directory holding it. |

From a matching entry, `regenerateWith` is the entry's command as written, and `generatedFrom` is
every existing repository file the command names (`-i`, `--input`, `--input-spec`, `--schema`,
`--spec`, `-input`, `-source`, or a plain argument). Globs, variables, URLs, and absolute paths are never expanded or
followed. A resolved header source outranks the entry's inputs.

| Where a command runs | Rule |
|----------------------|------|
| `go:generate`, `package.json`, `Makefile` | the directory of the file that holds it |
| CI `run:` | the step's `working-directory`, else the job's, else the workflow's `defaults.run.working-directory`, else the root; a computed value (`${{ matrix.dir }}`) skips the step |
| After `cd dir &&` | `dir`, when literal; a computed `cd` (or `cd -`) ends the entry; inside `( … )` the `cd` lasts until `)` |

An output that is the directory the command runs in, or a directory above it (`--go_out=.`,
`--go_out=..`), would claim every file below it, so it names nothing. An unknown flag's value (`--template t.yaml`) cannot be told apart from an
input, so it is listed in `generatedFrom` too.

Every string read from the repository (commands, header literals, script names) is cut to 512
characters, has credentials redacted and control characters removed, and is replaced by
`[withheld: reads like an instruction]` when it reads like one. Each directory and the workflows
contribute at most 5,000 commands; a cap that is reached is disclosed.

## The `generated-file-edited` finding

Advisory by default. `verify_change` classifies it with [`enforcement.policy`](configuration.md):
`blocking` sets `gated: true`, and `off` drops it. `openlore enforce` does not collect it.

| Diff | Finding |
|------|---------|
| A generated or vendored file is modified, and neither its known source nor the config file holding its command changed | `warning` (`info` for a `path-pattern` match). The message names the source and command, or says the source is unknown. |
| A lockfile is modified, and no manifest of its ecosystem at or below its directory changed | `info` |
| A generated file is added, deleted, or only renamed (no lines changed) | none: a generator run adds files, and a move is not an edit |

## Not built

Running generators, checking that generated output is up to date, and blocking the edit.
