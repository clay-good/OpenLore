# Generated-file guard

Agents edit generated code, vendored code, and lockfiles by hand. The edit passes, then the next
`protoc`, `openapi-generator`, or `npm install` erases it. The guard tells the agent that a file is
generated, and names its source and the command that regenerates it, when the repository says so
literally. It never runs a generator and never blocks an edit.

| Where | What you get |
|-------|--------------|
| `orient` | `generatedFiles`: the files in scope that are generated, vendored, or lockfiles |
| `blast_radius` | `generated`: the same marks for the files the diff changed |
| `verify_change` | the advisory `generated-file-edited` finding, one receipt item per file, and `findings[]` |

Each mark is `{ file, rule, matched, kind, generatedFrom, regenerateWith, evidence?, configFile?, certainty }`.

## Detection: closed rules, first match wins

| Order | Rule | Matches | `certainty` |
|-------|------|---------|-------------|
| 1 | `header-marker` | a marker below, in the first 40 lines (and 8 KiB) of the file | `declared` |
| 2 | `gitattributes` | `linguist-generated` or `linguist-vendored` set for the path (read with `git check-attr`) | `declared` |
| 3 | `lockfile` | a lockfile name below | `declared` |
| 4 | `path-pattern` | `*.d.ts`, `*.generated.*`, `generated/`, `__generated__/`, `vendor/`, `vendored/`, `node_modules/` | `path-pattern` |

An explicit `linguist-generated=false` (or `-linguist-generated`) in `.gitattributes` opts a path out
of rule 4. Use it for a hand-written `.d.ts`.

### Header markers

A header that matches none of these is **not** detected.

| Id | Recognized line |
|----|-----------------|
| `go-code-generated` | exactly `^// Code generated .* DO NOT EDIT\.$` ([Go convention](https://go.dev/s/generatedcode)) |
| `at-generated` | a comment whose first token is `@generated` |
| `generated-do-not-edit` | one comment line that says `generated` (or `auto-generated`) and `DO NOT EDIT` / `DO NOT MODIFY`, any case |
| `auto-generated-banner` | a comment line with `<auto-generated>`, `AUTO-GENERATED FILE`, or `This file is/was (automatically) generated` |

A comment line starts with `//`, `#`, `/*`, `*`, `--`, `;`, `<!--`, or `%`. Text in a string literal
or inside prose is not a marker.

## Source and command: literal only

`generatedFrom` and `regenerateWith` are `unknown` unless one of these names them:

| Evidence | Read from |
|----------|-----------|
| Header source line | `source: order.proto`, or `generated from openapi.yaml`, in the header comment. Resolved against the file's directory, then the root; a path that does not resolve is reported as written. |
| Config entry | A `//go:generate` directive, a `package.json` script, or a `Makefile` recipe in the file's directory or any parent directory, or a `run:` step in `.github/workflows/*.yml`. The entry must name an output path (`-o`, `--out`, `--output`, `--output-dir`, `--out-dir`, `--outdir`, `--outDir`, `--output-path`, protoc `--*_out=`, or `>`) that is the file or a directory holding it. |

From a matching entry, `regenerateWith` is the entry's command as written, and `generatedFrom` is
every existing repository file the command names (`-i`, `--input`, `--input-spec`, `--schema`,
`--spec`, or a plain argument). Globs, variables, URLs, and absolute paths are never expanded or
followed. A resolved header source outranks the entry's inputs.

## The `generated-file-edited` finding

Advisory by default; set its class with [`enforcement.policy`](configuration.md).

| Diff | Finding |
|------|---------|
| A generated or vendored file is modified, and neither its known source nor the config file holding its command changed | `warning` (`info` for a `path-pattern` match). The message names the source and command, or says the source is unknown. |
| A lockfile is modified, and no manifest of its ecosystem at or below its directory changed | `info` |
| A generated file is added or deleted | none: a generator run adds files |

## Not built

Running generators, checking that generated output is up to date, and blocking the edit.
