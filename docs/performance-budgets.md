# Deterministic performance budgets

OpenLore guards the cost of repository analysis and serving with counts of work, not elapsed time. The CI-visible tests in `src/core/analyzer/hash-keyed-analyze.test.ts`, `src/core/analyzer/analyze-pass-reuse.test.ts`, and the serving and watcher suites pin work on fixed fixtures: calls through the shared tree-sitter parse boundary, native query compilations, type inferences, full node-table loads, adjacency builds, and the explicitly scoped EdgeStore statement prepares and atomic artifact payload bytes. The SQL and byte baselines use small, real boundary fixtures; they are not claims about all I/O or CPU use. Worker-thread parses do not appear in the parent process's counters, so parse budgets exercise the serial extraction lane; separate tests check worker/serial output equivalence.

The assertions use the exact count observed on the fixture. When a legitimate change increases one, update the baseline in the same PR and state the old count, new count, and reason in its description. Do not widen a threshold just to accommodate an unexplained regression. Decreases should lower the baseline. The MCP and Pi standing-context budgets follow the same rule for payload growth: record the measured byte/token delta and explain the additional surface rather than silently bumping headroom.

Run `npm run test:unit` for the CI-visible work budgets, `npm run test:equivalence` for artifact equivalence, and `npm run test:budgets` for the separate hostile-input timing guards. These commands are separate steps in `.github/workflows/ci.yml`; the timing guards are security limits, not the deterministic performance baseline.
