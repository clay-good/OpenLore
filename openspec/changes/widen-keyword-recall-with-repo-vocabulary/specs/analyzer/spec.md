# analyzer spec delta

## ADDED Requirements

### Requirement: RepositoryVocabularyIsMinedDeterministicallyAndBounded

The analyzer SHALL mine a repository vocabulary lexicon from material it already extracts —
identifiers, doc comments, literal keys, and file paths — containing abbreviation-to-expansion
links, term co-occurrence links, and conservative morphological variants. Every mined entry SHALL
be evidenced within the analyzed repository; no entry SHALL come from an external dictionary, a
network request, or a language model. A small, source-declared seed set of universal programming
abbreviations MAY be included.

**Subsequence containment alone is NOT sufficient.** An abbreviation link SHALL additionally
satisfy all of: (1) the short form is at least 3 characters; (2) its first character equals the
long form's first character; (3) the long form is at most 3× the short form's length; (4) the
pair is attested in at least 2 distinct binding sites. Measured on this repository's 19,819-token
vocabulary, the bare subsequence predicate links `id` to 2,360 long forms, `os` to 3,347, and
`db` to `debug`, `describe`, and `codebase` alike; these four guards reduce each of those to zero
while retaining `cfg`→`config` and `svc`→`service`.

An entry SHALL be recorded only when **both** of its forms are present in the keyword corpus's
document-frequency table, since a term absent from that table contributes exactly zero at query
time and recording it would report an expansion that provably did not act.

**Mining SHALL be bounded and SHALL NOT be an all-pairs comparison.** Abbreviation candidates
SHALL be generated by a bucketed join — long forms indexed by first character and length band,
consulted only for short forms in that bucket — so candidate generation is linear in vocabulary
size. Co-occurrence pairing SHALL be capped at a declared maximum number of tokens per binding
site and per call neighborhood. Mining SHALL carry a declared wall-clock budget; on exhaustion it
SHALL stop and emit the partial lexicon marked `partial` with the omitted-candidate count
disclosed, never silently truncated and never extending the analyze beyond its budget. Measured
baseline: naive all-pairs generation over this repository's vocabulary costs 6.8 s and yields
841,316 unfiltered candidates.

The lexicon SHALL be byte-deterministic for a given repository state and SHALL be persisted with
a version stamp **and** a content stamp derived from the mined corpus's identity; it SHALL be
ignored and rebuilt when either does not match. A version stamp alone is insufficient: the
incremental update path patches the keyword index and deletes the corpus sidecar without
re-running analyze, so a format-stamped lexicon would be served indefinitely against a moved
repository. When the incremental path invalidates the corpus sidecar it SHALL invalidate the
lexicon by the same mechanism; until a rebuild completes, retrieval SHALL disclose plain keyword
mode rather than expand against an unverified lexicon.

Mining SHALL be fail-soft: an unreadable input, an unsupported language, or a disabled setting
SHALL yield an empty lexicon and SHALL NOT fail the analyze.

#### Scenario: Subsequence containment alone is rejected

- **GIVEN** the tokens `db` and `describe` co-occurring in a binding position
- **WHEN** the lexicon is mined
- **THEN** no link is recorded — `db` is shorter than 3 characters and `describe` exceeds 3× its
  length

#### Scenario: An abbreviation is discovered from in-repo evidence

- **GIVEN** a repository declaring `cfg: Config` in at least two binding sites
- **WHEN** the repository is analyzed
- **THEN** the lexicon links `cfg` to `config`, evidenced by the in-repo bindings

#### Scenario: A term the corpus cannot score is never recorded

- **GIVEN** a candidate expansion absent from the keyword corpus's document-frequency table
- **WHEN** the lexicon is mined
- **THEN** the entry is not recorded

#### Scenario: Mining stays within its budget

- **GIVEN** a repository whose candidate generation would exceed the declared wall-clock budget
- **WHEN** the repository is analyzed
- **THEN** mining stops at the budget, the lexicon is marked `partial`, the omitted count is
  disclosed, and the analyze is not extended

#### Scenario: A watcher save does not leave a stale lexicon serving

- **GIVEN** a mined lexicon and a subsequent incremental index update from a file edit
- **WHEN** a search runs before the next full analyze
- **THEN** the lexicon is not served, the disclosed mode is plain keyword, and no query is
  expanded

### Requirement: VocabularyExpansionIsQuerySideAndTwoTierRanked

Vocabulary expansion SHALL be applied at query time only. The persisted keyword index SHALL NOT
be expanded, SHALL NOT grow, and SHALL NOT require a rebuild when expansion is toggled.

**Ranking SHALL be two-tier, not weighted.** For each document the retrieval layer SHALL compute
an **original score** (over the original query tokens only) and an **expansion score** (over the
expansion tokens only) as separate quantities, and SHALL order by
`(originalScore > 0) desc, originalScore desc, expansionScore desc, id asc`. Consequently every
document with any original-term match SHALL rank above every expansion-only document,
unconditionally and independently of term count, idf, or corpus statistics.

A scalar weight multiplier SHALL NOT be used to express this property: the scoring function sums
over terms without bound, so no constant multiplier can guarantee it — a document matching five
high-idf expansion terms outscores a document matching one low-idf original term at any positive
weight that is not itself a no-op.

The two-tier ordering SHALL be applied to the sparse candidate list **before** truncation and
**before** rank fusion, so that no original-term match is evicted from the candidate window by an
expansion-only document, and so the tiering is not erased by fusion that consumes ranks and
discards score magnitudes.

The number of expansion terms per original query token SHALL be bounded by a declared cap.
Expansion SHALL be disableable by configuration, and with it disabled the ranking SHALL be
identical to the pre-change ranking with no re-index.

Expansion SHALL be applied uniformly at every keyword query path sharing the tokenizer — the code
index, the spec index, and the line-text index — or every path where it is deliberately not
applied SHALL be enumerated here with its reason. A path that silently diverges is not permitted.
Where a spec-prose query is expanded with a lexicon mined from code vocabulary, that
cross-corpus application SHALL be stated explicitly.

The lexicon SHALL be excluded from portable index bundles unless placed where the bundle
enumerator reaches it; an imported bundle without a lexicon SHALL disclose plain keyword mode and
SHALL NOT report the exporter's mode.

#### Scenario: Many strong expansion matches never outrank one weak original match

- **GIVEN** document A matching a single original query term with a low score contribution, and
  document B matching the maximum permitted expansion terms, each with high idf and high term
  frequency
- **WHEN** the search runs
- **THEN** A ranks above B, for every corpus size, idf distribution, and expansion cap

#### Scenario: An original match is never evicted from the candidate window

- **GIVEN** a query whose expansion-only matches would fill the truncated candidate list
- **WHEN** the search runs
- **THEN** the original-term match is present in the returned results

#### Scenario: A natural-language task query reaches abbreviated code

- **GIVEN** a repository containing `PmtSvc.chargeCard` whose doc comment attests the long form
  the query supplies, and a lexicon mined from it
- **WHEN** that query is searched in keyword mode
- **THEN** the symbol is among the ranked results, and the expansion terms that scored are
  returned

#### Scenario: Disabling expansion restores today's ranking

- **GIVEN** expansion disabled by configuration
- **WHEN** queries run against an unchanged index
- **THEN** the ranking is identical to the pre-change ranking, with no re-index
