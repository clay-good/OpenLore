# mcp-handlers spec delta

## ADDED Requirements

### Requirement: GeneratedFilesAreMarkedWithTheirSource

The system SHALL classify a file as generated or vendored by a closed, ordered rule set — a
recognized generator header marker, a `.gitattributes` generated or vendored attribute, a lockfile
name, or an existing excluded-path pattern — and record which rule matched. It SHALL record the
file's source (`generatedFrom`) and regeneration command (`regenerateWith`) only when a header or a
config-invoked entry (a `go:generate` directive, package script, CI run step, or build target) names
them literally, and SHALL record `unknown` otherwise. `orient` and `blast_radius` SHALL mark
generated files in their scope with these fields. `verify_change` SHALL report
`generated-file-edited` (registered, advisory) when a diff edits a generated file without also
changing its known source, or changes a lockfile without its manifest.

#### Scenario: A hand edit to generated code names its source

- **GIVEN** `gen/order_pb.go` with a `Code generated by protoc-gen-go. DO NOT EDIT.` header and a
  `go:generate` directive that runs protoc on `proto/order.proto` into `gen/`
- **WHEN** a diff edits only `gen/order_pb.go` and `verify_change` runs
- **THEN** a `generated-file-edited` finding names `proto/order.proto` as the source and the
  directive's command as the way to regenerate

#### Scenario: An unknown source is not guessed

- **GIVEN** a file with an `@generated` header and no config entry naming its input
- **WHEN** `orient` includes the file
- **THEN** it is marked generated with `generatedFrom: unknown`
